# API 서버 실행 메모 (Task 14)

systemd 유닛 파일(`deploy/labor-rag.service`)은 Task 18에서 만든다. 이 문서는 그때 유닛에 그대로 옮길 **실행 방식과 이유**다.

## 실행 명령

```
uvicorn app.api.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

- `--factory`: `create_app()`을 **인자 없이** 불러 앱을 만든다. 설정은 환경 변수와 작업 폴더의 `.env`에서 읽는다
  (필수 값이 빠졌거나 비밀번호 해시 모양이 틀리면 서버가 **시작할 때** 멈춘다 — 첫 요청이 아니라).
- `--workers 1`: **반드시 1개.** 이유 두 가지.
  1. 로그인 시도 제한 기록(`LoginThrottle`)이 프로세스 메모리에 있다. 워커가 둘이면 기록이 갈라져서 한도가 사실상 두 배가 된다.
  2. 대화 체크포인트(SQLite)와 `test` 계정의 IP별 횟수를 한 프로세스가 쓰는 것을 전제로 설계했다(스펙 6.1).
- `--host 127.0.0.1`: 웹서버(Caddy/Nginx, Task 18)만 접근한다. 직접 인터넷에 열지 않는다.

## 프록시 뒤에서 IP를 읽는 규칙

`test` 계정의 "같은 IP에서 5회"는 `X-Forwarded-For`를 **접속 주소가 `trusted_proxies`(기본 `127.0.0.1`)일 때만** 읽는다.
웹서버가 같은 서버의 127.0.0.1에서 8000으로 전달하므로 기본값이면 된다. 웹서버가 다른 주소에서 전달하면
`LABOR_TRUSTED_PROXIES='["…"]'`(JSON 목록)로 알려 준다. **Task 18에서 확인할 것**: 실제 웹서버가 `X-Forwarded-For`를 붙이는지,
클라이언트가 보낸 같은 이름의 헤더를 덮어쓰는지(덮어쓰지 않아도 코드는 오른쪽에서부터 읽어 안전하지만 확인한다).

## 로그인 쿠키

세션 쿠키는 `Secure`(HTTPS에서만 전송)다. 그래서 일반적으로 **HTTPS 없이 http로 접속하면 브라우저가 쿠키를 돌려주지 않아 로그인이
유지되지 않는다.** 이 동작은 테스트(주소를 `https://test`로 둔 클라이언트)로만 확인했다. 실제 브라우저에서의 동작은 확인하지 않았다.
추정(근거 없음, 확인 필요): 브라우저가 `http://localhost`를 예외로 취급해 Secure 쿠키를 허용할 수 있다 — Task 15·18에서
브라우저로 직접 확인하고, 안 되면 개발용으로 쿠키의 Secure 여부를 설정으로 빼는 것을 검토한다.

## 비밀번호 해시를 `.env`에 넣기

사용자가 자기 PC에서 `scripts/make_password_hash.py --account admin|test`를 실행하고, 출력된 한 줄(`LABOR_…_PASSWORD_HASH='$2b$12$…'`)을
서버의 `.env`에 옮긴다. 값은 작은따옴표로 감싼다(`$` 때문). python-dotenv로는 따옴표 유무와 상관없이 그대로 읽히는 것을 확인했다.
**systemd가 `EnvironmentFile`로 읽을 때도 그대로인지는 아직 확인하지 않았다** — Task 18에서 서버에서 확인한다
(앱이 시작할 때 해시 형식을 검사하므로, 값이 변형되면 서버가 시작을 거부하고 어느 변수가 문제인지 알려 준다).
