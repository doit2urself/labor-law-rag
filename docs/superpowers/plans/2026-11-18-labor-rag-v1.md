# 근로·노동 상담 RAG v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 법제처 법령 본문과 고용노동부 법령해석에서 근거를 찾아 출처와 함께 설명하는 근로·노동 상담 웹 서비스를, 월 청구액 0원으로 만든다.

**Architecture:** LangGraph가 고정 파이프라인(질문 분석 → 검색 → 리랭크 → 충분성 판단 → 생성 → 코드 검사 → LLM 검증 → 분기)을 돌리고, BM25(Nori)·벡터·RRF·필터는 OpenSearch 쿼리 하나가 처리한다. LLM·임베딩·리랭커·검색은 인터페이스(포트) 뒤에 두어 교체 가능하게 하고, 테스트는 가짜 구현체로 한다. FastAPI(+SSE)와 React 화면을 한 대의 Contabo VPS에 `systemd`로 올린다.

**Tech Stack:** Python 3.11+, FastAPI, LangGraph/LangChain(`langchain-google-genai`), OpenSearch(Nori), Cohere Rerank, SQLite, Langfuse Cloud, React 18 + Vite + TypeScript.

**Spec:** `docs/superpowers/specs/2026-11-18-labor-rag-design.md` (근거 자료: `docs/research/2026-11-17-rag-v1-design-review.md`). 실행자는 두 문서를 모두 읽는다.

## 실행 규칙

- 🔑 = 사용자가 키·계정·승인을 줘야 하는 단계, 🧑 = 사용자가 직접 하는 단계, 🚦 = 결과를 사용자에게 보고하고 답을 받기 전에는 다음 Task로 가지 않는 관문.
- 서버(SSH) 작업은 명령마다 사용자 승인을 받고, 서버를 바꾸는 작업은 먼저 무엇을 하는지 알린다(스펙 6.10). 첫 확인은 읽기 전용 명령으로 한다.
- 이 폴더는 아직 git 저장소가 아니다. Task 1에서 `git init`을 하고, 커밋은 사용자가 실행 방식을 승인할 때 함께 허락받는다.
- 테스트는 `.\.venv\Scripts\python.exe -m pytest <경로> -v`로 실행한다(옆 프로젝트 README와 같은 방식). 외부 서비스가 필요한 테스트는 `@pytest.mark.integration`을 달고, `pytest.ini`의 `addopts = -m "not integration"`로 기본 실행에서 뺀다. 서버에서만 `-m integration`으로 돌린다.
- 외부 API의 요청·응답 형식은 이 계획이 추측하지 않는다. 해당 Task가 가리키는 공식 문서를 읽고 그대로 따른다.
- 각 Task를 끝내면 사용자에게 한글로 5줄 이내의 학습 메모를 남긴다: 만든 파일, 읽는 순서, 핵심 개념 2~3개. (사용자의 요청이며, 실행 스킬의 "한 줄 서술" 규칙보다 우선한다.)
- 세션을 끝낼 때는 Task 경계에서 끊는다: 커밋, 원장(ledger) 기록, 기억 파일의 "다음 할 일" 갱신을 마친 뒤에만 사용자에게 `/clear`를 권한다.
- **스킬은 `superpowers:*`와 Claude Code 내장 스킬만 쓴다**(사용자 지시). gstack·GSD·dwf·document-skills·anthropic-skills 등 다른 플러그인 스킬은 쓰지 않는다.

## Global Constraints

모든 Task의 요구사항에 아래가 포함된다. 값은 스펙에서 그대로 옮겼다.

- Python 3.11 이상, `langchain-core` 1 이상. 버전 기준: langchain 1.5.0, langchain-core 1.8.1, langgraph 1.2.22, langchain-google-genai 4.5.0, langfuse 5.2.0, ragas 0.4.4, OpenSearch 3.9.0 이상. 표에 없는 패키지(`opensearch-py`, `cohere`, `langgraph-checkpoint-sqlite`, `httpx`, `fastapi`, `bcrypt`, `itsdangerous`)는 구현 시점의 최신을 `pip index versions`로 확인해 `requirements.txt`에 고정한다.
- `langchain-community`와 `langchain-classic`의 `BM25Retriever`·`EnsembleRetriever`는 쓰지 않는다.
- 월 청구액 0원. 유료 요금제·유료 API·새 서버 구입 금지.
- Docker 미사용. 앱은 `systemd` + `venv`, OpenSearch는 tarball(또는 deb) + `systemd`.
- 비밀번호·API 키는 저장소에 두지 않는다. 서버 `.env`에만 두고, 비밀번호는 bcrypt 해시로만 둔다.
- 임베딩은 `gemini-embedding-2`, 768차원. 청크마다 모델명과 차원을 기록한다.
- OpenSearch: Nori(색인과 검색에 같은 분석기), RRF `rank_constant` 60, 하위 쿼리 깊이 100~200 → RRF 뒤 상위 20, 하이브리드 하위 쿼리 최대 5개, 필터는 하이브리드 쿼리 안에서, 외부에 노출하지 않음(`127.0.0.1`).
- 리랭크: Cohere Rerank 5, 후보 20 → 5. 월 950회에 이르면 끄고 RRF 상위 5개로 대신한다.
- LangGraph: 재생성 ≤ 2, 재검색 ≤ 2, 질문당 LLM 호출 ≤ 8. 매 턴 시작에 재시도 카운터와 검색 결과를 초기화(누적 필드는 `Overwrite`). `thread_id`는 UUID(255자 미만). `recursion_limit`은 25(안전망). 클라이언트에는 `custom` 이벤트만 보내고, 생성 호출에 `nostream` 태그를 단다.
- 계정: `admin` 무제한, `test`는 같은 IP에서 누적 5회(IPv6는 /64). 질문 접수 = 1회, 서버 오류는 차감하지 않음. 초과 문구 `"이 IP의 사용 횟수(5회)를 초과했습니다."`
- 화면 고정 문구: `"법률 자문이 아닙니다. 출처의 원문을 확인하세요"`, `"출처: 법제처 국가법령정보센터"`, `"개인정보를 입력하지 마세요"`
- `uvicorn`은 `--workers 1`.
- 평가: 홀드아웃 해석(30~50건)은 색인에서 제외. 정답은 (법령명, 조문번호). 질문 라벨은 `answerable`·`verdict`·`no_evidence`·`out_of_scope`.
- Langfuse Cloud Hobby(월 50,000 units, 30일 보관). 개인정보 마스킹은 기록에만 적용하고 LLM 입력은 원문 그대로.
- 법제처 데이터를 보여 주는 모든 화면과 답변에 법제처 출처를 표기한다.
- **코드 주석은 한글로 쓴다**(사용자가 소스를 읽으며 학습하기 위함. 식별자·외부 API 이름은 영어 그대로).
  - 모듈 맨 위에 역할·사용처·입출력을 적은 한글 docstring, 공개 함수·클래스마다 한글 docstring(무엇을/왜, 인자·반환).
  - 코드만으로 의도가 안 보이는 곳과 LangGraph 상태 초기화·RRF·Nori·인용 검증 같은 개념이 나오는 곳에는 "왜 이렇게 했는지"를 한글 주석으로 설명한다.
  - 코드에서 바로 보이는 동작을 되풀이하는 주석은 달지 않는다. 테스트 함수 위에는 무엇을 검증하는지 한글 한 줄을 단다.

## Review Focus

스펙이 직접 다루지 않지만 사용자가 마주칠 가능성이 높은 입력·상황이다. 각각의 테스트는 해당 Task에 들어 있다.

1. **Gemini·Cohere 한도 초과·시간 초과** → 스택 트레이스 없이 "오늘의 무료 사용 한도가 소진되었습니다. 나중에 다시 시도해 주세요"를 보여 주고, 사용 횟수는 차감하지 않으며, 리랭크는 RRF 상위 5개로 대신한다. (Task 8, 10, 14)
2. **같은 IP에서 동시에 들어온 `test` 요청** → 정확히 5개만 성공한다. (Task 5, 14)
3. **위조된 `X-Forwarded-For` 헤더** → 신뢰하는 프록시(`127.0.0.1`)가 아닌 곳에서 온 헤더는 무시한다. (Task 14)
4. **빈 질문·공백만 있는 질문·1,000자를 넘는 질문, 검색어 속 `"` `*` `\`** → 검증 오류로 거절하고 차감하지 않으며, 검색 쿼리에는 일반 문자로만 들어간다. (Task 6, 14)
5. **문서 본문 속 지시문("이전 지시를 무시하고…")과 존재하지 않는 인용 ID** → 지시문은 데이터 구역 안에만 있고 따르지 않으며, 없는 인용 ID는 코드 검사가 잡는다. (Task 12)
